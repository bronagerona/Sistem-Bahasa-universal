# ILIS V2.2 — Beta Candidate Release Notes

**Status:** Beta Candidate (technical verification completed; not a production release)  
**Branch:** `ilis-v2-development`  
**Tanggal dokumentasi:** 2026-11-19  
**Repositori:** `bronagerona/Sistem-Bahasa-universal`

## 1. Ringkasan

ILIS V2.2 memperkenalkan percakapan multi-turn dengan pengelolaan sesi pada lapisan adapter. Riwayat percakapan disimpan sementara di memori proses, dibatasi hingga lima pasangan turn terbaru secara default, dan dapat digunakan sebagai konteks terbatas untuk memahami pesan lanjutan.

Versi ini mempertahankan prinsip ILIS sebagai sistem deterministik tanpa LLM. Core tetap stateless: adapter mengelola sesi dan meneruskan snapshot konteks untuk pemrosesan satu permintaan.

Dokumen ini menandai V2.2 sebagai **Beta Candidate berdasarkan pengujian otomatis dan skenario Playground yang tercatat**. Status ini bukan klaim kesiapan produksi atau jaminan bahwa semua variasi bahasa dan rujukan percakapan telah didukung.

## 2. Fitur utama

- **SessionManager in-memory:** membuat dan mengelola sesi percakapan terpisah.
- **Riwayat terbatas:** maksimal lima pasangan pesan pengguna–assistant tersimpan/digunakan sebagai konteks secara default.
- **Konteks multi-turn:** pesan lanjutan dapat dibaca dengan bantuan snapshot riwayat sesi yang sama.
- **Isolasi sesi:** riwayat satu sesi tidak dicampur dengan sesi lain.
- **Reset percakapan:** perintah reset membersihkan riwayat percakapan sesi aktif tanpa menghapus Knowledge atau Episodic Memory.
- **Integrasi adapter:** ChatbotAdapter dan GameEngineAdapter mendukung identitas sesi percakapan sesuai tanggung jawab adapter.
- **Kompatibilitas persona:** skenario Mode A (ILIS), Mode B (identitas aplikasi), dan Mode C (identitas NPC) tetap diuji.
- **Instruksi register:** pengujian memastikan instruksi gaya pada giliran saat ini, seperti sopan/formal, tetap diterapkan.

## 3. Batas arsitektur dan kompatibilitas

Batas berikut dipertahankan pada V2.2:

| Area | Ketentuan |
|---|---|
| Semantic | Kontrak tetap 12 field; tidak ditambah field riwayat |
| Reasoning | Kontrak tetap 6 key |
| ILIS Core | Stateless; tidak memiliki transcript/session store |
| Session | Dikelola oleh adapter melalui SessionManager in-memory |
| Context snapshot | Membantu interpretasi pesan; bukan bukti fakta |
| Knowledge / SQLite Core | Skema dan penyimpanan inti tidak diubah oleh fitur multi-turn |
| Episodic Memory | Tetap terpisah dari transcript percakapan |
| AI eksternal | Tidak menggunakan LLM atau panggilan model AI |

## 5. Batasan yang diketahui

1. Riwayat percakapan bersifat **in-memory** dan hilang ketika proses berhenti atau dimulai ulang.
2. Penyimpanan transcript persisten lintas restart belum disediakan.
3. SessionManager tidak menyediakan autentikasi, otorisasi, atau kepemilikan tenant. Host aplikasi wajib memvalidasi pemanggil dan session ID.
4. Context snapshot terbatas pada riwayat sesi yang tersedia; ia bukan mesin coreference umum dan tidak menjamin semua kata ganti atau rujukan implisit dapat diselesaikan.
5. Jika konteks ambigu atau pengetahuan tidak tersedia, hasil dapat tetap tidak pasti atau tidak didukung.
6. Pengujian A–E membuktikan skenario yang tercantum, bukan seluruh kombinasi percakapan di dunia nyata.
7. V2.2 belum merupakan sertifikasi keamanan, privasi, skalabilitas, atau kesiapan produksi.
8. Konsep penalaran berbasis kategori / Concept Engine adalah backlog untuk V3, fitur tersebut TIDAK termasuk di dalam cakupan V2.2-beta.

## 6. Panduan penggunaan dan integrasi

- Buat atau gunakan Session ID yang dikelola host untuk satu ruang percakapan.
- Teruskan Session ID yang sama untuk pesan-pesan dalam percakapan yang sama.
- Gunakan Session ID berbeda untuk percakapan/pengguna/NPC yang harus terisolasi.
- Validasi hak akses Session ID di sisi host sebelum memanggil adapter.
- Gunakan reset untuk menghapus riwayat percakapan sesi aktif; reset tidak menghapus Knowledge atau Episodic Memory.
- Jangan mengandalkan riwayat in-memory setelah restart proses.
- Jangan memasukkan data pribadi, kredensial, atau informasi rahasia ke lingkungan uji.

Detail API dan contoh kode tersedia di [Panduan Developer Multi-Turn V2.2](multi_turn_v2_2_developer_guide.md). Prinsip pemisahan Core, adapter, session, dan storage dijelaskan di [Dokumen Arsitektur Multi-Turn V2.2](multi_turn_v2_2_architecture.md).
